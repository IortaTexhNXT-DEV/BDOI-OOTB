## Observations and remaining limitations

- **Numbering after the reset.** The transaction reset restarts every transaction series, including the next numbers the
  configuration workbook set above the old system's numbers. The rehearsal loads the configuration workbook again after
  the reset (32 Numbering rows updated, everything else unchanged); without it the migration refuses every legacy number
  of the series' format. Documented in `SMOKE_TEST_AND_RESET.md` and `GO_LIVE_DATA_WORKBENCH.md`; a reset option that
  keeps the counters the Numbering sheet set would remove the manual step.
- **Zero-balance accounts.** The opening balance import refuses an account row with neither a debit nor a credit ("The
  row has no amount"). A trial balance export usually lists accounts whose movements net to zero (2 in this run); the
  rehearsal leaves them out. Accepting an explicit zero as "no balance" would spare the broker the clean-up.
- **All-or-nothing errors.** When one opening balance row is wrong, every other row is reported "Not loaded ... fix the
  other rows" in row order, so the real error sits among them in the list. The rehearsal sorts the real errors first in
  its own output; the screen and the errors workbook do not.
- **Migrated bill numbers.** An open item gets a new bill number of the invoice series; the old system's bill number is
  kept as the bill reference (e.g. `INV-2026-00067` with reference `INV-2026-00004`). With the same format in both
  systems this is easy to confuse; search the open receivables by the reference.
- **Commission rate screen.** The Line of Business check of fix 2 is in the workbench only; the Commission Rate Matrix
  API (`POST /commission-rates`) still accepts any code.
- **Receivables control account.** The SOURCE ledger carries 610.40 on `POL-2026-00027`, a policy cancelled on the cutover
  day (its credit is dated on the cutover), so it is not migrated as in force while its balance is in the trial balance
  at cutover - 1. The rehearsal explains the control account difference policy by policy and passes when it equals the
  GL balances on policies not migrated; in a real cutover the old system is frozen at cutover - 1 and the difference is
  0 or a reconciling item for the accountant.
- **As-at view.** The open book at cutover - 1 (in-force policies, bill balances with later receipts and credits added
  back, open claims) is read from SOURCE's database (`SOURCE_DATABASE_URL`, read-only transaction): the API has no
  as-at view of receivables. The trial balance comes from the API (`GET /accounting/trial-balance?asOf=`).
- **Personas.** Persona users of the configuration workbook sign in with the temporary password the load returns once.
  On a re-run, or when a run stopped before their first sign-in, the administrator resets their password, which is
  slower (sign-in rate limit).

## How this run was set up

PostgreSQL 16 locally; two databases migrated and seeded with reference data only (`SEED_SAMPLE_DATA=false`); two API
instances of this checkout (`NODE_ENV=production`, `SCHEDULER_ENABLED=false`, throwaway secrets and passwords). SOURCE
was loaded with the UAT scenario (`node scripts/uat-scenario.js`, 371 steps, none failed) and two authority limits were
changed and approved there by two administrators (so the maker-checker of the limits is exercised on TARGET). TARGET
started empty. Re-running the rehearsal on the same TARGET (pre-flight reset of the earlier run's business) passes too.
