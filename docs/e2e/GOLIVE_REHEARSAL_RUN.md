## Observations and remaining limitations

- **Numbering after the reset.** Fixed (defect 5): the reset restarts each series at the next number the Numbering sheet
  set (policy at `POL-2026-00068`, journal at `JV-2026-00195`), the configuration export after the reset equals the one
  after step 2, and the workbook loaded again after the reset is all unchanged. A next number set before migration
  `0246` is not recorded as a period start: load the Numbering sheet once more after upgrading.
- **Zero-balance accounts.** Fixed (defect 6): the 2 accounts netting to zero are now in the Opening Balances sheet and
  are ignored by the load.
- **All-or-nothing errors.** Fixed (defect 6): the unbalanced trial balance of step 4.4 is one sheet message, the 19
  rows are held.
- **Migrated bill numbers.** Fixed (defect 8): the 20 open items keep their SOURCE bill numbers (e.g. `INV-2026-00004`);
  the invoice series continues at `INV-2026-00067`, above them. When both systems use the same format, the invoice
  series' next number must be above the old bill numbers before the migration (the Numbering sheet from SOURCE does it).
- **Commission rate screen.** Fixed (defect 7).
- **Spreadsheet programs.** The round trip is checked with the file saved by openpyxl (numeric character references)
  and with Excel's `_x000D_` line breaks; it was not run through Excel itself.
- **Receivables control account.** The SOURCE ledger carries 610.40 on `POL-2026-00027`, a policy cancelled on the cutover
  day (its credit is dated on the cutover), so it is not migrated as in force while its balance is in the trial balance
  at cutover - 1. The rehearsal explains the control account difference policy by policy and passes when it equals the
  GL balances on policies not migrated; in a real cutover the old system is frozen at cutover - 1 and the difference is
  0 or a reconciling item for the accountant.
- **As-at view.** The open book at cutover - 1 (in-force policies, bill balances with later receipts and credits added
  back, open claims) is read from SOURCE's database (`SOURCE_DATABASE_URL`, read-only transaction): the API has no
  as-at view of receivables. The trial balance comes from the API (`GET /accounting/trial-balance?asOf=`).
- **Personas.** Persona users of the configuration workbook sign in with the temporary password the load returns once.
  On a re-run, or when a run stopped before their first sign-in, the administrator resets their password, which is
  slower (sign-in rate limit).

## How this run was set up

PostgreSQL 16 locally; two databases migrated and seeded with reference data only (`SEED_SAMPLE_DATA=false`); two API
instances of this checkout (`NODE_ENV=production`, `SCHEDULER_ENABLED=false`, throwaway secrets and passwords). SOURCE
was loaded with the UAT scenario (`node scripts/uat-scenario.js`, 433 steps, none failed). TARGET started empty.
Re-running the rehearsal on the same TARGET (pre-flight reset of the earlier run's business) passes too. This run
(after fixes 4 to 8) did not change SOURCE's authority limits first, so step 2 has no limit waiting for approval; the
first run exercised that maker-checker with two limits changed and approved on SOURCE by two administrators. The same
SOURCE workbook, saved by openpyxl and uploaded into SOURCE, reports all 797 rows unchanged.
