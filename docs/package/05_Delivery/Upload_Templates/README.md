# Upload templates

One workbook per upload that BrokerVerse accepts. Hand these to the people preparing go-live data and day-to-day bulk
uploads. Each workbook has three sheets:

- **Data**: the header row the importer reads, with one or two Philippine sample rows. Required columns have dark red
  headers. Delete the sample rows before uploading your own data.
- **Columns**: each column with required (yes, no or conditional), format, allowed values, an example and other header
  names the importer also accepts.
- **Instructions**: the screen to upload on, the API route, file types, row limit and what happens when a row is wrong.

The master templates can also be downloaded on the master screens that have an Upload button
(`GET /api/masters/<type>/template`), and the Chart of Accounts, Period Management (opening balances) and Collections
(open items) screens offer theirs. The Prospects, Quotations, Policy, Receipts and Disbursement bulk upload screens
offer a CSV with the same headers.

## Coverage

Every upload the platform accepts, the screen with its Upload (or Import) button, the API route and the template. A
master without an Upload button on its screen is uploaded through the API route by a System Administrator (for example
with the API collection exported by `npm run export:api`). The table is written by
`backend/scripts/build-upload-templates.js`; do not edit it by hand.

## Uploads without a template

| Upload | Why there is no template |
|---|---|
| Document and photo uploads (`POST /api/s3/upload`, `/api/s3/upload-multiple`): policy documents, IDs, vehicle photos, payment proofs, quotation responses, insurer offers, product documents, company logo | Single files stored as attachments, not rows of data |
| Claim documents (`POST /api/claims`, `PUT /api/claims/:id`, `PUT /api/claims/settle/:id`), endorsement document (`POST /api/endorsements/upload-document`), logo and favicon (`POST /api/system-settings/upload/:field`, `/logo-presets`) | Single files attached to the record |
| Bank statements of BDO, BPI and Metrobank | Upload the bank's own export with its format (BDO-SAMPLE, BPI-SAMPLE, MBT-SAMPLE); the generic template is for other banks. `POST /api/bank-reconciliation/formats/:code/test` tries a format on such a file |
| Insurer statements in an insurer's own layout | Set up the insurer's format (Master > Finance > Insurer Statement Formats) and upload the insurer's own file; the generic template is for insurers without a format |
| Employee Flow > Bulk Upload Employees (group quotation screen) | The screen only picks a file; nothing is sent to the API |
| Main Account and Sub Account masters | Copies of the chart of accounts; use the Chart of Accounts template (their upload is refused) |
| Account set-up (Master > Finance > Account Determination) | One record per fixed set-up code (Premium, Miscellaneous, Customer, RI claims), all shipped; edited on the screen (its upload is refused) |
| Retired masters: Taxation, Commission, Employee, Petty Cash and the retired Remittance Master records (Approval Workflow, Reconciliation Rule, Electronic Transfer, History Configuration, Analytics Configuration, Direct Bill, Report Template) | Retired by migrations 0233 and 0241; their values live on another screen (Premium Taxes & LGU Rates, Commission Rate Matrix, User Management > User, Petty Cash > Initiate, Authority Matrix, Configuration). Their upload and template download are refused and they have no template |
| Tax codes, Commission Rate Matrix, users and roles on the screen | No upload; entered on the screen (named users can be created in bulk with the Users provisioning file) |

## Keeping them in step with the code

The templates are generated, not edited by hand. The column lists come from the importers themselves:

| Upload | Source of the columns |
|---|---|
| Leads, quotations, policies, receipts, payment vouchers | `LEAD_UPLOAD_COLUMNS`, `QUOTE_UPLOAD_COLUMNS`, `POLICY_UPLOAD_COLUMNS`, `RECEIPT_UPLOAD_COLUMNS`, `DISBURSEMENT_UPLOAD_COLUMNS` in the module services; the importers map rows with the same lists |
| Chart of accounts | `ACCOUNT_UPLOAD_COLUMNS` (`backend/src/modules/accounting/service.js`) |
| Opening balances, open items | `OPENING_BALANCE_COLUMNS` (`period-end/opening.js`), `OPEN_ITEM_COLUMNS` (`receipts/opening.js`) |
| Masters | the field definitions of the master type (`master_types`, seeded in `51_masters.sql` and changed by later migrations); samples, menu paths and file names in `backend/src/modules/masters/uploadSamples.js`. Every active master type that takes an upload gets a template; retired types (status inactive) get none |
| Bank statement | the GENERIC statement format (`bank_statement_formats`) |
| Insurer statement | the GENERIC insurer statement format (`insurer_statement_formats`) |
| Remittance bulk processing | the field mappings of the Bulk Processing master (BFM-001) |
| Remittance bank transactions, users | the screen parser (`brokerverse/src/module/Remittance/Reconciliation/index.js`) and `backend/scripts/provision-users.js`; the test checks the headers against both |

Regenerate after changing an importer, a master type, a statement format or the bulk-processing configuration:

```
cd backend
DATABASE_URL=postgres://... node scripts/build-upload-templates.js      # writes ../docs/package/05_Delivery/Upload_Templates
```

The script also removes the templates of uploads the platform no longer accepts and rewrites the coverage table above.

`backend/test/upload-templates.test.js` builds the templates and checks that:

- every API route that receives a file is listed in `FILE_ROUTES` of the build script, with its template or the reason it
  has none;
- every master type that takes an upload has a template, sample rows and a menu path, and no retired type has one;
- this folder holds exactly the generated files and the coverage table is current;
- each template is read back by its importer's own parser and column list (a header the importer no longer reads fails);
- the sample rows of every master template and of the insurer statement are accepted through the API on a database with
  reference data only; the go-live imports (policies, open items, opening balances) load their templates;
- the CSV templates offered by the bulk upload screens have the importer headers.

## Manual verification

The 39 templates delivered before the insurer statement and the remaining master templates were added were also
verified by hand: a backend with a fresh database (migrated and seeded with `SEED_SAMPLE_DATA=true`) received the
sample rows of each template, unchanged, through the real API as the System Administrator, in the order of the coverage
table. Opening balances and open items were loaded with go-live date 2027-01-01, because the sample data already has
posted journals in fiscal year 2026 (a go-live date after posted journals of the same fiscal year is refused). The bank
statement was imported into bank account ACC-BDO-001 with format GENERIC. Each upload was accepted with no failed row.
