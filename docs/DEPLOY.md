# Hosting BrokerVerse

The branch `brokerverse-platform` holds the revised application: the front end in `brokerverse/`, the
Node.js + PostgreSQL backend in `backend/`, and two ready deployments. The original code is untouched on the
other branches.

## Option 1: Render (public URL, no servers to manage)

1. Sign in at render.com and connect the GitHub account that can read this repository.
2. Choose **New > Blueprint**, pick this repository and the branch `brokerverse-platform`. Render reads
   `render.yaml` and proposes three resources: the database `brokerverse-db`, the API `brokerverse-api` and
   the web app `brokerverse-web`.
3. Fill in the values Render asks for:

   | Service | Setting | Value |
   |---|---|---|
   | brokerverse-api | ADMIN_PASSWORD | the administrator's first password |
   | brokerverse-api | CORS_ORIGINS | the web URL, e.g. `https://brokerverse-web.onrender.com` |
   | brokerverse-api | PUBLIC_BASE_URL | the API URL, e.g. `https://brokerverse-api.onrender.com` |
   | brokerverse-web | REACT_APP_BASE_URL | the API URL + `/api` |

4. Apply. The API migrates and seeds the database on start (settings, masters, chart of accounts,
   scheduled jobs, the administrator `BrokerVerse`). Open the web URL and sign in.
5. Change the administrator password at once, then create the persona users under
   Master > Generals > User Management.

`JWT_SECRET` is generated by Render. Uploaded documents are kept on a 1 GB disk mounted on the API.
For e-mail, add `SMTP_URL` (for example `smtps://user:password@smtp.example.com:465`) to the API.

## Option 2: Docker Compose (own server or cloud VM)

```
export JWT_SECRET=$(openssl rand -hex 32)
export ADMIN_PASSWORD='<first administrator password>'
export DB_PASSWORD='<database password>'
docker compose up --build -d
```

Open `http://<server>:8080`. The web container serves the front end and forwards `/api` to the API
container; PostgreSQL data and uploads are kept in Docker volumes. Put a TLS proxy (for example Caddy
or an AWS/Azure load balancer) in front of port 8080 for a public HTTPS URL, and set `CORS_ORIGINS` and
`PUBLIC_BASE_URL` to that URL.

## Checks after deploying

| Check | How |
|---|---|
| API up | `GET <api>/api/health` returns `{"status":"ok"}` |
| Sign in | BrokerVerse with the ADMIN_PASSWORD |
| Configuration | Master > System Settings and Master > Configuration load |
| Schedules | Master > Schedules lists the jobs; run "Receivable ageing" once |
| API documentation | `backend/docs/api` holds the OpenAPI file, the Postman collection and the Excel touchpoint list |

## Before production use

- Change the default administrator password, and never keep the example value in `docker-compose.yml`.
- Set up daily database backups (Render does this on paid plans; with Docker, schedule `pg_dump`).
- Review the open items in `docs/e2e/DEFECTS.md`, in particular payment capture and KYC at policy issue.
- The container cannot be tested inside this development sandbox (no Docker daemon); the same backend
  and front-end builds were run directly and passed the end-to-end test in `docs/e2e/E2E_REPORT.md`.
